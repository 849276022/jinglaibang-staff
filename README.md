# 警来帮 · 失物招领工作台（民警端 Demo）

地铁警务便民服务「警来帮」的**民警/客服处置端**演示，与群众端语音寻物大屏配套。
纯前端单文件（HTML + 原生 JS + localStorage），**双击 `staff-lostfound-demo.html` 即可在浏览器打开**，无需安装、无需后端。

## 功能（五个区，按业务流程从上到下）

0. **待登记 · 丢失询问**：群众在语音大屏询问后采集的信息先排队，**不直接出正式单**；民警核对详情后点「登记建档」生成正式 LF 工单进入待匹配，信息不全可「退回」通知群众补充（比群众自助出单多一道民警把关，防乱报）。
1. **待匹配 · 追踪码（LF）**：正式 LF 单排队等待；点击一行可将物品类型/颜色/线路/站点自动回填到录入表单。
2. **录入捡获失物**：民警把实际捡到的物品登记入台账，提交即按「物品类型 + 颜色/站点」自动反向匹配待匹配的 LF 单，命中后生成 6 位取件码。
3. **失物台账**：按 全部 / 在库 / 已命中 / 已领取 筛选；支持凭取件码核销发放、排除匹配（填复核原因）、查看实物照片与乘客认领反馈。
4. **待确认上交单（HD）**：乘客拾获后到大屏登记、携物到客服中心；民警凭上交码确认后自动入台账，未自动匹配时可手动绑定 LF 追踪码；详情含完整进度时间线。

## 状态流转

- 失物台账：`in_stock 在库` → `matched 已命中` → `claimed 已领取`
- 乘客上交单：`pending 待交付` → `confirmed_at_desk 已到客服` → `matched 已找到失主` → `closed 已结案`
- 所有发放动作需二次确认 + 6 位取件码校验，防止冒领。

## 数据说明

- 演示数据保存在浏览器 localStorage（键名 `jlb_staff_lostfound_demo_v1`），刷新不丢。
- 页面右上角「重置演示数据」可恢复初始样例（含 4 张 LF、2 件台账、2 张 HD）。
- 与真实生产系统隔离，仅用于流程演示与培训。

## 后续接入生产

将各数据操作替换为调用后端统一接口即可（与群众端共享同一套 lost-reports / lost-handovers / lost-items API）：

- 待匹配列表、台账列表、上交单列表：`GET`
- 录入实物、确认上交、手动绑定：`POST`
- 排除匹配、核销取件：`POST .../reject`、`POST .../release`（带取件码）

## 边界

本仓库只含**民警处置工作台**，不含群众端语音对话/报案界面（见另一个仓库 `jinglaibang-h5`）。
